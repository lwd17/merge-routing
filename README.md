# MERGE: Evidence Routing under State-Dependent Group Externalities

Anonymous code release for *"MERGE: Evidence Routing under State-Dependent
Group Externalities"* (under double-blind review).

Multi-agent search teams duplicate work and flood each other with evidence.
MERGE treats inter-agent communication as a **joint allocation problem over
source-grounded evidence-to-receiver transfers** and asks a question the
structural version of this method could only answer by assumption: *how does
the value of a piece of evidence change as more teammates are exposed to it?*

Instead of prescribing that curve with a phase schedule and hand-designed
reach/broadcast terms, **MERGE-Response measures it**. Paired interventions
on logged development states — assign the same evidence to `h-1` other
receivers, then add or withhold one focal transfer, and continue both
branches to the team's final answer — give terminal-utility labels. A small
response model `g_phi` is fitted to those labels, centered against the
single-holder reference, and integrated into an exposure potential that
enters the allocation objective:

```
F^resp(A) = sum_i U^theta_{i,t}(A_i)            learned receiver-local value
          + w_exp sum_c Psi_phi(c, A)           measured exposure response
          - w_load C_load(A) - w_tok T(A) - w_dup C_dup(A)

Psi_phi(c,A) = sum_{r=b_ct}^{b_ct+k_c(A)-1} gamma_phi(t,c,r)
gamma_phi(t,c,h) = g_phi(x_{t,c,h}) - g_phi(x_{t,c,1})
x_{t,c,h} = (d_t, h/N, delta/N, delta, 1/N, q_c),  delta = m - h
```

No monotonicity constraint, fixed early/late sign, or majority-peak template
is imposed, so the fitted response may show diminishing returns, a threshold
peak at the majority crossing, or neither. Because threshold complementarity
breaks submodularity, every arm shares a **beam + compound-move solver**
rather than positive-singleton greedy construction. The online allocator
still makes **zero routing LLM calls**.

**Scope.** This repository contains the method, every arm of the comparison,
the intervention-collection and training protocol, and the analysis that
produces each results table. It contains **no experimental results or run
logs**; `RESULTS.md` is generated by `scripts/make_report.py` from runs you
execute yourself.

## 1. Installation and serving

Python >= 3.10, Java 21 (Pyserini/Lucene), and an OpenAI-compatible endpoint.

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt && pip install -e .

python -m vllm.entrypoints.openai.api_server \
    --model <backbone> --port 8100 --max-model-len 8192
```

| Variable | Meaning |
|---|---|
| `CQP_API_BASE` / `CQP_API_BASES` | endpoint, or a comma-separated fleet (tasks are stably hashed to one endpoint so prefix caching works) |
| `CQP_MODEL`, `CQP_API_KEY` | model id and key |
| `CQP_NO_THINK=1` | suppress thinking traces on reasoning-mode backbones |
| `CQP_DATA_ROOT`, `CQP_DATASET` | data root and active dataset |
| `CQP_BUDGET_MAIN=B` | per-step global cap for the budget sweep — a pure feasibility constraint, never a target dose |
| `CQP_CLUSTER_TAU` | online clustering threshold (default 0.62) |
| `CQP_ROLES=1` | optional role-specialized search instructions |
| `CQP_SEMVAL`, `CQP_RESPONSE`, `CQP_PHASE`, `CQP_GLOBALSET` | override model checkpoints |
| `CQP_WEXP_RESP` | exposure weight for the response potential (selected on development data) |

## 2. Data

```bash
python scripts/hotpotqa_setup.py      # also musique_setup.py, make_2wiki.py
python scripts/make_hotpot_manifest.py --n 400 --seed <SEED> --exclude <used manifests>
```

Draw **question-disjoint** manifests for discovery, fitting, selection and
confirmation, disjoint also from the local scorer's training questions.
Every state, seed, cluster and branch of a question must stay in one split.

## 3. Arms

| Code arm | Paper arm | Exposure term |
|---|---|---|
| `no_comm` | No communication | — |
| `capped_full` | Capped full | broadcast under the same hard caps |
| `separable` | Separable | none (objective factorizes exactly) |
| `structural` | Structural (original MERGE) | `tau_t` schedule with `f_broad` / `f_reach` |
| `learned_phase` | Learned-Phase | fitted `tau_eta(d)`, same structural terms |
| `global_set` | Global-Set | generic joint set predictor |
| `merge_response` | **MERGE-Response** | centered learned potential `Psi_phi` |
| `resp_raw_encoding`, `resp_no_distance`, `resp_concave`, `resp_uncentered`, `resp_greedy` | response ablations | see below |

All optimized arms share the same candidate construction, the same frozen
local scorer, and the same beam/compound solver, so differences come from the
objective and not from the search. `resp_greedy` is the solver-only control.

## 4. End-to-end protocol

```bash
# (a) log development states under a fixed collection mixture
python scripts/run_experiment.py --manifest <dev>.json --out runs/dev \
    --arms separable,capped_full,structural

# (b) paired terminal-utility interventions -> training labels
python scripts/collect_interventions.py --records runs/dev/records.jsonl \
    --out runs/interventions/n4.jsonl --n-agents 4 --reps 3 --splits runs/splits.json

# (c) fit g_phi and the learned controls (development splits only)
python scripts/train_response.py --interventions runs/interventions/n4.jsonl \
    --out src/merge/search/response_model.npz --fit-phase --fit-global-set

# (d) frozen evaluation on held-out confirmation questions
python scripts/run_experiment.py --manifest <confirm>.json --out runs/confirm \
    --arms capped_full,separable,structural,learned_phase,global_set,merge_response \
    --seeds 3

# (e) tables
python scripts/analyze_response.py --interventions runs/interventions/*.jsonl
python scripts/analyze_policy.py  --records runs/confirm/records.jsonl
python scripts/analyze_solver.py  --records runs/dev/records.jsonl
python scripts/make_report.py --out RESULTS.md
```

Freeze `theta`, `phi`, the hyperparameters and the solver before step (d).
Never fit the response model on evaluation records.

## 5. Output format

`<out>/records.jsonl` holds one JSON object per (task, arm, seed):

```
task_id, arm, seed, question, answer (gold), gold_docids, n_agents, rounds,
events       per-agent per-round query, retrieved docs, routed items,
alloc_log    per-step solver log: construct/final value, depth, accepted
             moves, package size, objective-evaluation count, wall-clock,
finals       per-agent answers with F1/EM,
group        team answer (strict majority, else plurality with source-count
             then lexical tie-breakers), with F1/EM,
comm_tokens  transmitted inter-agent tokens,
total_tokens input+output across every LLM call (the efficiency metric),
memory_pool, pool_stats, team_gold_coverage, wall_seconds
```
